[Autumn](https://useautumn.com) एक ओपन-सोर्स लेयर है जो Stripe और आपके एप्लिकेशन के बीच काम करती है, जिससे आप कोई भी प्राइसिंग मॉडल बना सकते हैं और इसे कुछ लाइनों के कोड से एम्बेड कर सकते हैं। Autumn पर आप निम्नलिखित बना सकते हैं:
- सब्सक्रिप्शन
- क्रेडिट सिस्टम और टॉप अप
- उपयोग-आधारित मॉडल और ओवरेज
- बड़े ग्राहकों के लिए कस्टम प्लान

यह सब बिना webhooks, अपग्रेड/डाउनग्रेड, कैंसलेशन या पेमेंट फेल को हैंडल किए।


## शुरुआत करना

**क्लाउड**: Autumn का उपयोग शुरू करने का सबसे तेज़ तरीका हमारी [क्लाउड सर्विस](https://app.useautumn.com) है।

**सेल्फ होस्टेड**: यदि आप Autumn को सेल्फ-होस्ट करना चाहते हैं:

1. सुनिश्चित करें कि आपके पास `bun` इंस्टॉल है
2. प्रोजेक्ट की डिपेंडेंसी इंस्टॉल करें
```bash
bun install
```
3. हमारी सेटअप स्क्रिप्ट चलाएं:
```bash
bun setup
```

4. अपने postgres DB में आवश्यक टेबल जेनरेट करें
```bash
bun db:generate && bun db:migrate
```

5. Autumn चलाएं:

Windows के लिए
```bash
docker compose -f docker-compose.dev.yml up
```

Mac/Linux के लिए:
 ```bash
docker compose -f docker-compose.unix.yml up
```

बस इतना ही! आप `http://localhost:3000` पर Autumn डैशबोर्ड देख सकते हैं।

> ⚠️ लॉग इन करने के लिए, साइन इन पेज पर एक ईमेल दर्ज करें, और एक OTP आपके कंसोल / टर्मिनल में दिखाई देगा। सामान्यतः, हम OTP ईमेल करने के लिए Resend या Google OAuth का उपयोग करते हैं -- इन्हें `server/.env` में अपनी क्रेडेंशियल्स प्रदान करके सेटअप किया जा सकता है

> ℹ️ हमारी सेटअप स्क्रिप्ट आवश्यक env vars और (वैकल्पिक रूप से) एक Supabase इंस्टेंस को इनिशियलाइज़ करती है। यदि आप अपना Postgres इंस्टेंस उपयोग करना चाहते हैं, तो आप ऐसा कर सकते हैं -- बस कनेक्शन स्ट्रिंग को `server/.env` में `DATABASE_URL` env वेरिएबल में पेस्ट करें

## समस्या निवारण

यदि आप पहले से `bun setup` चलाने के बाद फिर से चलाने पर `SyntaxError: Unexpected end of JSON input` एरर का सामना करते हैं, तो आपको पहले अपने डेटाबेस टेबल को साफ़ करना पड़ सकता है। यह एक [ज्ञात समस्या](https://github.com/drizzle-team/drizzle-orm/issues/4529) है जो डेटाबेस माइग्रेशन को कई बार चलाने पर हो सकती है।

इसे हल करने के लिए:

1. अपने डेटाबेस से कनेक्ट करें
2. सभी मौजूदा टेबल ड्रॉप करें
3. सेटअप स्क्रिप्ट फिर से चलाएं:


## Autumn क्यों

**1️⃣ बिलिंग इन्फ्रास्ट्रक्चर तेज़ी से जटिल हो जाता है**

यह सिर्फ पेमेंट से अधिक है: यह permission management, metering, cron jobs के साथ usage limits बनाना, और इसे अपग्रेड, डाउनग्रेड, कैंसलेशन और फेल पेमेंट स्टेट्स से कनेक्ट करना है। Race conditions, edge cases, और अन्य bugs आपको धीमा कर देंगे।

**2️⃣ बिलिंग और ऐप लॉजिक को अलग होना चाहिए**

बढ़ती कंपनियां अक्सर प्राइसिंग पर iterate करती हैं: कीमतें बढ़ाना, क्रेडिट के साथ प्रयोग करना या नई फीचर के लिए चार्ज करना। DB माइग्रेशन, इन-ऐप फ्लो को फिर से बनाना, कस्टम प्राइसिंग के लिए इंटर्नल डैशबोर्ड और पुरानी प्राइसिंग पर यूज़र्स को grandfathering करना एक दुःस्वप्न है।


## यह कैसे काम करता है
सबसे पहले, डैशबोर्ड पर अपने प्रोडक्ट और प्लान बनाएं। हम **किसी भी** प्राइसिंग मॉडल को सपोर्ट करते हैं। कुछ लोकप्रिय जो हमने देखे हैं:

1. **उपयोग और ओवरेज** ⚡: रियल-टाइम उपयोग सीमा सेट करें और चुनें कि वे कब रीसेट हों। यदि यूज़र्स सीमा से अधिक जाते हैं तो उन्हें चार्ज करें।
2. **क्रेडिट** 💰: यूज़र्स मौद्रिक या मनमाने क्रेडिट एक्सेस कर सकते हैं जिनसे कई फीचर्स उपयोग कर सकते हैं
3. **सीट-आधारित प्रति-सीट सीमा के साथ** 👥:: ग्राहकों को उनके यूज़र्स (या अन्य एंटिटीज़) के लिए बिल करें
4. **अग्रिम भुगतान** 💳: यूज़र्स को एक फीचर की निश्चित मात्रा अग्रिम खरीदने दें, जो समय के साथ उपयोग की जाती है


इसके बाद, आपकी सारी बिलिंग लॉजिक केवल 3 फ़ंक्शन के माध्यम से लागू की जा सकती है:

1. `/attach`: सभी खरीद फ्लो के लिए एक फ़ंक्शन कॉल। हम एक Stripe Checkout URL रिटर्न करते हैं, या एक अपग्रेड/डाउनग्रेड हैंडल करते हैं।

```tsx
const { attach } = useAutumn();
<button
  onClick={async () => {
    await attach({ productId: "pro" });
  }}
>
  Pro में अपग्रेड करें
</button>
```

2. `/check`: जांचें कि क्या ग्राहक के पास किसी प्रोडक्ट, फीचर या शेष उपयोग तक पहुंच है।
```ts
const { check } = useAutumn();

const { data } = await check({ featureId: "ai_tokens" })

!data.allowed && alert("AI सीमा समाप्त")
```

3. `/track`: जब कोई ग्राहक उपयोग-आधारित फीचर का उपयोग करता है, तो एक उपयोग इवेंट रिकॉर्ड करें।

```ts
const { track } = useAutumn();

await track({
  featureId: "ai_tokens",
  value: 1312
})
```
